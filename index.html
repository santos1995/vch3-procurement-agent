Procurement Agent : AI-assisted procurement: from site requirement to vendor comparative

Vibe Coders Hackathon Edition 3 · Vinayak Group problem statement · Demo package: waterproofing, Vinayak Amara Tower-2 (structure from the public brief; all values invented)

Demo data. Every vendor name, rate, quote and performance score here is invented for the hackathon demo. The agent recommends, it never selects a vendor, sends an email, places an order or pays. RFQs below are drafts for test inboxes only. Deterministic steps are labeled rule-based; AI drafting is labeled when it is really AI.

1Capture the site requirement rule-based

A site engineer's informal note (form / WhatsApp / transcribed voice note) parsed into a structured BOQ. Unknown units are flagged, never silently converted.

2Match to ERP item codes rule-based

Matches each BOQ line to an existing item code, suggests a new one when none fits, and flags likely duplicates, a variant (e.g. 450 mm wall vs 200 mm wall) is flagged for confirmation, not auto-merged.

3Draft RFQs to vendors draft only, test inboxes

One RFQ draft per vendor for the category. Nothing is sent, a human sends real RFQs, and the hackathon rule is test inboxes only.

4Read vendor replies rule-based parser

Supported reply formats: rate table, email prose, chat-style text, and scanned-PDF text. Anything the parser cannot read is flagged as unreadable, never guessed. GST, freight, payment terms and delivery time are normalised when present; missing ones are listed.

5Comparative statement rule-based

Like-for-like comparison on quoted rates. Landed cost uses only what the vendor actually quoted; gaps stay flagged. Past-performance scores are SIMULATED. No real vendor performance records exist at Vinayak.

6Recommendation to HOD rule-based

Every ranking carries a plain-words reason. The HOD message is drafted by Sarvam 105B through a hardened proxy when reachable, otherwise by a rule-based template, the badge says which. A human makes the final call.
